# evaluation/

The demonstration eval harness for the i2b2-ML LLM module. Consumes
`i2b2_cdi.LLM` as a library and produces the results table for the
JAMIA Open paper.

This directory is independent of the Flask app, the jobWatcher daemon,
and any live i2b2 Postgres database — the script reads a cohort CSV
directly and writes results into a per-run directory with a sqlite
audit log.

## Files

| File | Purpose |
|---|---|
| `run_demonstration.py` | The main script. CLI + library entry point `run(...)`. |
| `synthetic_cohort.csv` | 50-row deterministic synthetic cohort (25 HF+, 25 HF-). Generated by `_synthetic_cohort.py`; checked in for reproducibility. |
| `_synthetic_cohort.py` | Generator for the synthetic cohort. Re-run to regenerate (seed=42). |
| `sample_config.json` | Example eval config matching `LLM_MODULE_SPEC §2.5`. Provider = `mock` so the script runs end-to-end offline. |
| `_eval_mock_provider.py` | `EvalMockProvider` — a note-aware MockProvider used for the offline demo. Heuristic HF labels based on keywords in the note. **Not** for real eval — swap in `anthropic` / `local_hf` / `ollama` in `sample_config.json`. |

## Quick start

```bash
# Run against the synthetic cohort with the offline mock provider
python evaluation/run_demonstration.py \
    --cohort  evaluation/synthetic_cohort.csv \
    --config  evaluation/sample_config.json \
    --out-root evaluation/results
```

Outputs land in `evaluation/results/<UTC-timestamp>/`:

```
raw_predictions.csv     One row per cohort patient (subject_id, hf_gold,
                        llm_label, llm_confidence, llm_evidence, runtime_ms,
                        prompt_tokens, completion_tokens, cost_usd, status,
                        attempts, note_excerpt)
metrics_summary.json    n_total, n_processed, n_failed, confusion matrix,
                        accuracy, sensitivity, specificity, PPV, NPV,
                        cohen_kappa, auroc_confidence, total_runtime_s,
                        total_cost_usd, audit_rows_written
confusion_matrix.csv    2x2 table
error_analysis.csv      Subset of raw_predictions where llm_label != hf_gold
                        (or status='failed'); includes note excerpt + evidence
run_config.json         Full snapshot of provider/prompt config, cohort path,
                        cohort row count, git commit hash, git dirty flag,
                        python version, UTC timestamp
run_log.txt             Full loguru output of the run
audit.sqlite            Per-call audit rows via PromptAuditLogger
                        (same schema as production llm_audit)
```

## Swapping in a real provider

Edit `sample_config.json` (or write a new file) replacing the `provider`
block:

```json
"provider": {
  "name": "anthropic",
  "model": "claude-sonnet-4-5",
  "external_provider": true
}
```

`external_provider: true` is **required** for any external provider — see
`LLM_MODULE_SPEC §2.0` for the PHI-leaves-Docker safety rationale. The
opt-in gate accepts only Python `True` or the case-insensitive string
`"true"` (see H-1 fix).

For Ollama (default `http://localhost:11434`):

```json
"provider": {"name": "ollama", "model": "llama3"}
```

For self-hosted vLLM / LM Studio via the OpenAI-compatible API:

```json
"provider": {
  "name": "openai_compatible",
  "base_url": "http://my-vllm:8000/v1",
  "model": "meta-llama/Meta-Llama-3-8B-Instruct",
  "api_key": "...",
  "external_provider": true
}
```

For local HuggingFace transformers (requires `pip install transformers
accelerate torch`):

```json
"provider": {
  "name": "local_hf",
  "model": "meta-llama/Meta-Llama-3-8B-Instruct"
}
```

## Running on real MIMIC data

After PhysioNet DUA approval, run `sql/cohort_v1.sql` against BigQuery
(or PostgreSQL with the `physionet-data.` prefix removed) to produce a
real cohort CSV. The harness consumes any CSV with the columns
`subject_id, hadm_id, note_id, note_date, text, hf_gold`.

```bash
bq query --use_legacy_sql=false --format=csv \
    < sql/cohort_v1.sql > /tmp/mimic_cohort.csv
python evaluation/run_demonstration.py \
    --cohort  /tmp/mimic_cohort.csv \
    --config  evaluation/my_anthropic_config.json \
    --out-root evaluation/results
```

## Tests

```bash
pytest tests/evaluation/ -v
```

5 tests cover smoke, metrics correctness against a known-perfect mock
(kappa = 1.0), provider-failure handling (half of cohort hits
TimeoutError, harness doesn't crash, n_failed reported correctly),
reproducibility receipt (run_config.json contains git SHA + cohort
metadata + python version), and audit-sqlite population.

## Architectural choices worth noting

- **Single-threaded.** Audit ordering stays deterministic and reproducible.
  Parallelization is a follow-up if needed for scale.
- **Audit lands in sqlite, not the live PG.** This script runs anywhere
  with a Python venv; it doesn't need the i2b2 Docker stack to be up.
  Production paths through `apply_LLM.run_label` still write to the
  live `llm_audit` table — this harness uses the same `PromptAuditLogger`
  class but with a `SqliteAuditDataSource` shim.
- **Reuses the LLM module without modification.** Both `EvalMockProvider`
  and the harness import from `i2b2_cdi.LLM.*` and call public functions
  (`get_provider`, `SchemaValidator`, `HallucinationGuard`,
  `coerce_text_to_dict`, `retry_with_backoff`, `compute_prompt_hash`,
  `render_prompt`, `PromptAuditLogger`).
- **Per-run timestamped output directory.** Multiple runs don't overwrite
  each other; you can diff results across runs.
